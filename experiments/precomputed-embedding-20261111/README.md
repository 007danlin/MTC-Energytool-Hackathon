# E1: предварительный индекс BGE-M3 поверх A2

Это отдельный эксперимент по Q&A №32. Рабочие исходники в корне проекта и архив A2 с результатом 55.969 не изменены. G, получивший 51.729 по сообщению пользователя, также сохранён.

Индекс содержит 234 вектора полных разделов предоставленной базы, три контрольных вектора и метаданные. `embedding_index.json`, `embedding_vectors.bin` и `hybrid_retrieval.py` находятся рядом с `solution.py` в корне экспериментального ZIP. Веса модели, вопросы, эталонные и готовые ответы в ZIP отсутствуют. Все вычисления при запуске выполняются стандартной библиотекой Python; загрузки моделей и установки дополнительных пакетов нет.

Зафиксирована BAAI/bge-m3, revision `5617a9f61b028005a4858fdac845db406aefb181`: CLS, L2, float32, 1024 измерения, без префикса. Полные документы не усекались: максимум 660 токенов. Локальная модель поддерживает 8192 токена; среди контрольных текстов есть текст длиннее 512 токенов для обнаружения несовместимого ограничения длины. См. [официальную модель](https://huggingface.co/BAAI/bge-m3).

Сначала проверяются модель, формат, хеш векторов и точное соответствие ID/текста всех разделов текущей базы. Затем три контрольных текста отправляются через общий API `/embeddings` с `EMB_MODEL` (по умолчанию `BAAI/bge-m3`) и теми же адресом/ключом, что используются генерацией. Минимальное косинусное сходство контрольных векторов — 0.999. Проверка обнаруживает существенное расхождение модели, pooling и обработки текста, но не доказывает совпадение на всех возможных запросах. Доступ к настоящему API платформы пока не предоставлен.

Поиск использует фиксированный RRF с k=60, равными весами и 24 кандидатами из лексического и плотного поиска. Выбираются 12 разделов; дополнительные полные ограничения из A2 сохраняются. Лимит контекста — 32000 символов. Никакого подбора весов по ответам модели в этом эксперименте нет.

При несовпадении базы/модели, повреждении индекса, несовместимых контрольных векторах или ошибке API используется исходный поиск A2. Ошибка API отключает векторную ветку до конца запуска; повторных безуспешных вызовов для каждого вопроса нет. Запрос длиннее 4096 символов идёт в лексический поиск без усечения. На старте проверка ограничена 10 секундами, отдельный запрос — 5 секундами, учитывается общий срок выполнения и резерв 60 секунд. Диагностика `embedding_index` сообщает итоговый режим, причину и число вызовов без ключей и текстов запросов.

Воспроизведение и доказательства:

- `reports/private/embedding-20261111/experiment.json` — состояние и заранее выбранные условия сравнения.
- `encode_and_serve.py`, `model-info.json`, `model/`, `venv/` в той же папке — официальный локальный кодировщик и сохранённые зависимости; повторное построение не нужно. Скрипт запускается через `venv/bin/python3`, готовый индекс/кеш запросов не пересчитывает.
- `compare_retrieval.py`, `retrieval-summary.json`, `retrieval-cases.json` — сравнение трёх поисков на 35 уже открытых случаях. Закрытый holdout не использован.
- `build_zip.py`, `package.json` — воспроизводимая сборка с фиксированным составом и SHA; отказывается перезаписывать существующий архив.
- `tests/test_index.py`, `validation-unit.log` — 15 проверок загрузки, API, несовместимости и возврата к A2.
- `docker/validation.json` — запуск точного ZIP в Python 3.9, 512 МБ, 2 CPU, без сети; реальные сохранённые векторы воспроизводятся тестовым API, генерация замокана. Это проверка протокола, а не качества ответов.
- `run-e1/` — отдельный прогон точного ZIP на реальной установленной Qwen30B и локальной BGE-M3; качество оценивается отдельно.
