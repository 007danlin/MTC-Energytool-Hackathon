# Корректировка backend по Q&A МТС

Изолированная копия на базе A2 (55.969). Основные файлы проекта и испытанные архивы F/G/H не перезаписаны. Это корректировка backend-контракта, не новый платформенный сабмит и не третья итерация CSV-промпта H.

- Для готовности обращения нужны подтверждённый телефон и намерение клиента; имя и компания необязательны. Email пока не поддерживается.
- `missing_fields` содержит только недостающий телефон; необязательные поля вынесены в `optional_missing_fields`.
- Новый `status=lead_step` предназначен только для контактного шага. Его текст формируется программно из проверенных контактов и цитат клиента; модельный текст отбрасывается. Продуктовый `answered` по-прежнему требует подтверждённых цитат.
- `summary.brief` содержит до двух проверенных цитат об актуальной задаче/условиях. Полная структурированная информация сохранена. Выбор актуальных цитат делает модель, поэтому смысловую актуальность всё ещё нужно оценивать на диалогах.
- `integration.save_prepared_lead(result, directory)` явно сохраняет подготовленное обращение в локальный UTF-8 TXT с телефоном и резюме. Отправки менеджеру нет. Веб-бэкенд должен вызвать функцию после подтверждённого обращения; автоматического сохранения каждой реплики нет.
- Версия контракта 1.1. Потребителю нужно принять новый статус `lead_step` и новые поля summary. Ответ `answer_only` и CSV-промпт не изменены.

Проверка: `python3 -m unittest discover -s tests` из этой папки — 73 теста прошли. Проверены минимальный контакт, отсутствие согласия/контакта, отказ, выдуманный телефон, сохранение TXT, блокировка продуктового ответа без источника; прежние тесты исправления и отзыва номера также проходят. Проверки используют синтетические ответы модели; качество её маршрутизации в `lead_step` на живой Qwen ещё не подтверждено. Результат на платформе не измерен.

`backend-qa.patch` содержит только отличия от A2 и новые тесты. Его не следует автоматически накладывать на основной рабочий вариант или смешивать с уже замороженным ZIP G. Основание: предоставленный `mts-qa-handoff-2026-11-10.md`, уточнения №14–17, 20–21, 44.
