# Диагностика результата и изменения v3

Дата: 10 ноября 2026 года. Цель работы — устранить воспроизводимые потери качества и подготовить следующий автоматический сабмит. Место в закрытой проверке не предсказывается по локальным тестам.

## Что означает результат v2

Источник измерений — таблицы, предоставленные пользователем в этом чате, а не собственный доступ к платформе:

| Версия / команда | Личный кабинет | Лидерборд | Другие сведения |
|---|---:|---:|---|
| MISISion possible, v2 | 5.836 | 0.0584 | Место 21, две попытки; показанная длительность 466.3 секунды |
| AIE-masters | Не предоставлено | 0.6938 | Место 1, шесть попыток в предоставленном снимке |
| MISISion possible, v1 | Ошибка | Не указан | 2.0 секунды; подробных логов нет |

`5.836 / 100 = 0.05836`, округление до четырёх знаков даёт `0.0584`. Это согласуется с двумя шкалами интерфейса; официальное описание самой UI-конвертации не предоставлено. Разрыв по показанным лидербордным значениям равен `0.6938 − 0.0584 = 0.6354` пункта шкалы 0–1.

По техническому регламенту `Score = 0.7 × MatchRate + 0.3 × WinRate`: первая составляющая — средняя оценка сравнений, вторая — доля побед без ничьих. Поэтому 5.836 нельзя называть процентом правильных ответов. Из итогового Score нельзя восстановить число проверочных вопросов, тексты ответов, долю ошибок API или обе компоненты оценки.

Наличие оценки v2 означает, что платформа выполнила оценивание. Оно не доказывает, что каждый вызов API завершился успешно: технические сообщения тоже могли попасть в CSV. 466.3 секунды — значение, показанное интерфейсом; состав этого времени неизвестен. Точная причина низкого Score остаётся неподтверждённой без фактических ответов платформенного запуска.

## Какие материалы исследованы

Изучены полный кейс PDF, технический регламент DOCX, задание Даниэля, оба предоставленных ZIP, зависимости, 18 демонстрационных вопросов и 18 примеров ответов. База содержит 19 Markdown-документов, 219 248 исходных байт и 234 извлекаемых раздела: четыре справочника, восемь документов об электроэнергетике и семь продуктовых документов.

В обоих CSV по 18 уникальных ID и нет пустых вопросов/ответов. Примеры ответов занимают 25–52 слова, медиана — 38. Это ориентир лаконичности, а не требование копировать образцы. Данные организаторов используются локально для индексации и оценки; демонстрационные ответы не участвуют в runtime и не входят в ZIP.

Предоставленные архивы принадлежат организаторам. Архивов решений AIE-masters или других команд среди материалов нет; их архитектура и причины результата 0.6938 неизвестны.

## Подтверждённые механизмы потери ответов

Проверки выполнены контролируемыми ответами тестового клиента. Это воспроизведение поведения кода, а не утверждение о фактическом ответе Qwen на платформе.

| Контролируемый ответ модели | Поведение v2 | Поведение v3 в CSV |
|---|---|---|
| Полезный обычный текст | Два вызова, затем технический отказ из-за отсутствия JSON | Текст сохраняется после одного вызова |
| JSON с полезным answer, но без contacts | Два вызова, затем отказ по схеме | Поле answer принимается; поля заявки не требуются |
| Полезный answer и неточная дословная цитата | Два вызова, затем отказ по цитате | Служебная цитата не блокирует answer |
| Рассуждения перед одиночным `</think>` | Рассуждения попадали в результат | Сохраняется только текст после закрытия |

Для CSV регламент требует только `id,answer`. Поля контактов, intent, summary и дословные цитаты туда не попадают. V3 запрашивает сразу краткий ответ клиенту; правила использования базы, сохранения оговорок, истории и отказа от контактов остаются в промпте. Полный контракт бэкенда остаётся отдельным режимом по умолчанию.

Автоматическая проверка дословной цитаты не была полноценной проверкой истинности ответа. В текстовом режиме `sources=[]`, а `debug.retrieved_sources` означает найденные фрагменты, не доказанно использованные источники. Качество и полнота ответа требуют оценки реальной модели.

## Измерение поиска v2 → v3

База в ZIP и распакованная база из Downloads побайтно совпадают по всем 19 файлам. Базовая версия для сравнения загружена прямо из сохранённого ZIP v2, включая его retrieval.py и dialogue.py. Результаты привязаны к SHA-256 исходников, базы, вопросов и разметки; хэши v3 сверены с итоговым ZIP. Сводка без текстов организаторов — `reports/retrieval-validation.json`.

Разметка содержит точные разделы базы, подтверждающие необходимые факты. Измеряется доля групп фактов, для которых найден хотя бы один подходящий раздел, а не простое вхождение слов в контекст.

| Метрика на 18 демовопросах, 25 группах фактов | v2 | v3 |
|---|---:|---:|
| Нужный источник на первом месте | 36% | 36% |
| Покрытие групп фактов в первых шести фрагментах | 80% | 100% |
| Покрытие групп в первых двенадцати | 88% | 100% |
| Все необходимые группы в первых двенадцати, вопросов | 16/18 | 18/18 |
| Покрытие групп во всём контексте | 96% | 100% |
| Медиана объёма контекста, символов | 18 491 | 8 391.5 |
| p95 объёма контекста, символов | 21 388 | 14 416 |

Медианный контекст сократился на 54.6%. Это снижение объёма входа, а не измеренное ускорение API. На 30 дополнительных вопросах наличие всех размеченных фактов в первых двенадцати фрагментах улучшилось с 28/30 до 30/30; медиана контекста — с 18 569.5 до 8 972 символов. p95 рассчитан методом nearest-rank. Все эти вопросы использовались при разработке, поэтому результаты не являются независимой оценкой обобщения.

Поиск теперь отдельно оценивает содержание и подзаголовки, учитывает текущую тему и историю с разными весами, сопоставляет общеязыковые варианты терминов и выбирает только относящиеся к теме справочные ограничения. Смена темы и возвращение к старой теме проверены отдельно. Готовых ответов, ID демовопросов и числовых продуктовых фактов в правилах поиска нет.

Есть отдельные регрессии ранга: например, нужный источник демовопроса 10 переместился с первого на четвёртое место. Первый результат в среднем не улучшился. Кроме того, старый полный контекст уже содержал 24 из 25 групп фактов; одним поиском нельзя объяснить низкий Score v2. Главный устранённый риск генерации — потеря пригодного ответа из-за схемы служебных полей.

## API и ограничения выполнения

Адрес, ключ и модель берутся из окружения платформы; запрос идёт на `/chat/completions` с Bearer-авторизацией. Контракт v2 соответствовал предоставленному регламенту. Веб-сервер и командный бэкенд для автоматического CSV-сабмита не нужны.

Тайм-аут по умолчанию увеличен с 60 до 90 секунд, как в примере организатора. Общий бюджет остаётся 1120 секунд; параллелизм по умолчанию — три запроса, платформенная настройка ограничена восемью. Ограниченные повторы 429/5xx и сетевых ошибок сохранены. Нестандартные параметры управления thinking, не обещанные регламентом прокси, не добавлены.

Неполное рассуждение и отдельное `reasoning_content` не используются как ответ. При `finish_reason=length` сохраняется явная техническая ошибка без повторения идентичного запроса: оборванная последняя оговорка может существенно исказить смысл. Это остаточный риск при недостаточном MAX_TOKENS, а не скрытый успешный ответ.

## Проверка сборки v3

`python3 tools/check_all.py --docker --python-compat python:3.9-slim` завершился успешно:

- 65 тестов на Python 3.12.14, столько же внутри Docker на 3.11.18 и на распакованном ZIP под 3.9.25.
- 30 локальных сценариев протокола, включая 18 демо в текстовом CSV-режиме и 12 сценариев бэкенда.
- Изолированный ZIP: 18 запросов, 18 непустых ответов, сохранены все ID, код выхода 0.
- Docker Compose: 18 строк CSV, 19 HTTP-запросов с одним намеренным 429 и успешным повтором; процесс UID 10001, данные только для чтения.
- Файлы контейнера совпадают с ZIP; тестовый ответ действительно доходит до CSV, технические заглушки не засчитываются как успех проверки.

Архив `artifacts/daniel-submission-v3.zip`: 22 668 байт, SHA-256 `8080cc06980f8dde184cc1320ccafca2dffd7a58b5a7ba6772bef177dde4ab09`. В корне только восемь Python-модулей и requirements.txt, без данных, готового индекса, тестов, ключей и внешних зависимостей. Обычный `artifacts/daniel-submission.zip` содержит те же байты; v2 сохранён отдельно.

Эти результаты подтверждают сборку и протокол. Все HTTP-ответы в данных локальных проверках создавал тестовый сервер, не Qwen.

## Проверка следующего результата

Следующий сабмит следует сравнивать с v2 по фактическому платформенному Score. Локальная проверка поиска не равна оценке генерации и не является прогнозом позиции в лидерборде. Демовопросы использовались при разработке; они не являются отложенной независимой выборкой. Дополнительные написанные вручную вопросы проверяют пограничные случаи, но не заменяют скрытую проверку.

Для повторной проверки доступны `tools/check_all.py`, `tools/retrieval_benchmark.py`, отчёты `reports/validation.json`, `reports/docker-validation.json` и `reports/python-compatibility.json`. Полные материалы и промежуточные измерения остаются в игнорируемой Git папке `reports/private/`.
