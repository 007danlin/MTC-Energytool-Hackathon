# Интерфейс консультации Георгия

Главная страница: http://127.0.0.1:8768. Под исходной кнопкой «Заказать консультацию» добавлена красная «Онлайн-консультация». Она открывает `/consultation.html` в той же вкладке. Исходное React-приложение МТС сохранено; плавающий старый чат заменён новым входом.

Источник дизайна — `design/georgy/Untitled (Copy).fig`. Структура прочитана локально из встроенной Kiwi-схемы: 2693 узла, страницы Desktop, Mobile, Components · User Flows. Компактная выгрузка размеров, текстов, цветов и шрифтов — `design/georgy/design-spec.json`. Базовые экраны: 2:30 (1440×960), 2:50 (390×844); исходный шрифт Inter подключён локально. В макете нет растровых иллюстраций: логотип набран текстом, как в оригинале.

## Реализованные действия

- Подсказки подставляют редактируемый вопрос, но не отправляют его.
- Чат отправляет сообщения в существующий Go API, который вызывает Python-консультанта и локальную Ollama. При неоднозначном сетевом сбое текст остаётся в поле. После обновления истории интерфейс проверяет, появилась ли отправленная реплика на сервере. Если она сохранена, поле очищается. Если сервер её не получил, пользователь может повторить отправку вручную.
- Меню: новый диалог, история, режим отладки, заявка, закрытие и возврат на сайт. Возврат на сайт через меню или логотип закрывает текущую сессию через API. Если набран вопрос или заполнена форма, перед выходом есть подтверждение. Закрытый диалог доступен для чтения, а повторный вход создаёт пустую сессию.
- Каждый новый ответ хранит `message.response` со статусом, временем и проверенными источниками. Режим отладки показывает эти данные для выбранной реплики, включая технический сбой. Для старых сессий без metadata используется `last_result` только у последнего сообщения.
- Контакты → проверка → сохранение → изменение → скачивание TXT. Телефон обязателен, имя и компания необязательны; резюме можно исправить перед подтверждением. Образцовые контакты и ответы из Figma не используются в рабочем диалоге.
- «Оставить заявку специалисту» доступно с первого экрана. При явном намерении в `lead.requested` интерфейс предлагает открыть форму уже после уточняющего ответа. После отказа от телефона клиент может продолжить разговор. Карточка сохранённой заявки появляется после ответа API с `application.saved_at`.
- Данные формы сохраняются отдельно от ML-черновика (`session.application`), поэтому новая генерация не может затереть подтверждённую заявку. Это сохранение для демонстрации, без внешней отправки в МТС или CRM.
- В адаптивной верстке сохранены исходные компоненты и размеры на 1440×960 и 390×844; на промежуточных размерах используются гибкие колонки. Формы работают с клавиатуры, модальные окна удерживают фокус, текст сервера экранируется.

## API заявки

`POST /api/v1/sessions/{id}/application`

```json
{"full_name":"","phone":"+7 999 123 45 67","company":"","summary":"Нужен раздельный учёт по арендаторам."}
```

Ответ — обновлённая сессия с `application.saved_at` от сервера. Повторное сохранение заменяет заявку этой сессии. Сервис проверяет номер (10–15 цифр), длины полей и непустое резюме. Нельзя сохранять заявку в закрытую сессию. Хранилище — прежний Docker volume, атомарный JSON-файл. Сохранение не изменяет ML evidence и не выдаёт форму за реплику модели.

## Запуск и проверка

```sh
docker compose -f compose.web.yaml up --build -d
(cd backend && go test -race ./... && go vet ./...)
python3 -m unittest tools.host_tests.test_web_stack -v
PLAYWRIGHT_MODULE=/path/to/playwright node tools/host_tests/test_consultation_ui.cjs
PLAYWRIGHT_MODULE=/path/to/playwright node tools/host_tests/test_consultation_states.cjs
```

Браузерная проверка использует запущенный сервер, создаёт тестовые сессии с вымышленными контактами и сохраняет скриншоты в `/tmp/mts-design-review` (переопределяется `WEB_TEST_SHOTS`). `WEB_TEST_URL` меняет адрес сервера. Она проверяет переход, подсказки, валидацию, редактирование/сохранение, TXT, reload, mobile, историю, изоляцию и возврат. Для ответа модели проводится отдельный live-прогон; тесты API не измеряют качество консультации.

Дополнительный браузерный набор с изолированными ответами проверяет неоднозначный обрыв сети, отсутствие автоматического повторного POST, восстановление истории, экранирование модельного текста и источников, повтор после технического сбоя и ширины 320/390/768/1024/1440. Он отделён от live-прогона модели.

### Приёмка с моделью

Для приёмки запустите [веб-связку с базой организаторов и моделью](web-stack.md). Откройте новый диалог перед каждым сценарием.

| Сценарий | Первый вопрос | Что показать |
|---|---|---|
| Рост счетов | «У нас три магазина, и выросли счета за электроэнергию. С чего начать?» | Уточнение по объектам, рекомендация, источник выбранного ответа. Затем исправьте телефон и резюме, сохраните заявку, скачайте TXT и откройте заявку после перезагрузки. |
| Учёт в СНТ | «В нашем СНТ часть домов без счётчиков. Как наладить учёт?» | Несколько ходов диалога. Перейдите к теме расходов, затем вернитесь к домам. Проверьте, что консультант учитывает прежние сведения о СНТ. |
| Неполные знания | «Можно ли подключить EnergyTool к нашей системе по самописному протоколу?» | Граница знаний и следующий шаг. Откройте заявку, выберите «Продолжить без телефона», задайте ещё вопрос. Закройте чат и найдите диалог без заявки в истории. |

Для записи основного сценария используйте вымышленные контакты. Зафиксируйте название модели, время, статусы и результат каждого прогона. Повтор после сетевого сбоя проверьте отдельно. Снимки и записи с имитацией ответов помечайте как техническую проверку интерфейса.

## Историческая проверка модели до настройки веб-адаптера

Связка UI → Go → Python → Ollama проверена живыми запросами. На вопрос об учёте первый запрос достиг бюджета 85 секунд, повтор завершился за 61,2 секунды с `ungrounded_citation`; сценарий про три магазина также вернул технический fallback. Локальная модель доступна, но её ответ не проходит существующую строгую проверку дословных цитат. Продуктовые ответы не считаются успешно принятыми. Эта проверка и ML-сабмит не изменялись. Форма заявки, её подтверждение и история работают независимо от генерации. Результаты перечислены в `reports/consultation-ui-validation.json`.

Дополнительный прямой диагностический вызов Python → Ollama для сценария про три магазина завершился `answered` после одного исправления цитат. Это подтверждает, что модель способна пройти валидацию, но не отменяет нестабильность живых браузерных прогонов.


## Повторная сверка с макетом: состояния и порядок

| Экран Figma | Условие | Элементы по порядку |
|---|---|---|
| 01–02c | Новый вход с сайта | Приглашение → три подсказки → редактируемое поле |
| 03 / 03r | Запрос в работе | Реплика клиента → подпись консультанта → ожидание |
| 04 | `clarification` | Реплика → уточнение → соответствующие вопросу быстрые ответы, без заявки |
| 05 / 05b | `answered` | Переписка → рекомендация → следующий шаг со специалистом |
| 06 | Запрошены контакты | Предыдущая переписка → пояснение → форма из трёх полей |
| 07 / 07u | Форма заполнена | Предыдущая переписка → пояснение → контакты и резюме → изменение / подтверждение |
| 09 / 09u | Подтверждение сохранено | Предыдущая переписка → подтверждение → карточка заявки → продолжение / история |
| 12 | Отладка | Данные конкретного ответа → список источников → отдельный фрагмент |
| 14 | `technical_error` | Вопрос → одна карточка ошибки → повтор; без предложения продукта |
| 15 / 15r | Без телефона | Предыдущая переписка → продолжение без контакта → возврат к заявке |
| 16 | `knowledge_gap` | Ответ → заявка / другой вопрос, без карточки рекомендации |
| 16b | `out_of_scope` | Ответ → другой вопрос, без заявки |
| @history / @archive | История | Список → отдельное окно сохранённого разговора; текущая сессия не подменяется |
| @edit / @edite | Изменение контактов | Модальная форма → inline-ошибка → сохранение или отмена |

Новый вход с главной использует `start=new`; после создания сессии параметр удаляется из URL, поэтому обычная перезагрузка восстанавливает текущий разговор. История в интерфейсе ограничена ID, открывавшимися в этом браузере, чтобы не показывать чужие тестовые сессии общего локального сервера. Это UX-фильтр, а не серверная авторизация.

Тексты содержательных ответов по-прежнему приходят из ML. Быстрые ответы из макета появляются только для соответствующего уточняющего вопроса; варианты про показания не подставляются под любой ответ. Примеры ответов Figma используются исключительно в изолированных браузерных тестах.

Главная: вход в онлайн-консультацию расположен в первом блоке страницы. Положение исходной кнопки входа сохранено. Плашка `new` привязана к правому верхнему углу новой кнопки. На телефоне под кнопку резервируется место.

В локальной копии кнопки входа в кабинет и исходная форма консультации недоступны. Рядом остаётся рабочая «Онлайн-консультация», а отметка внизу страницы поясняет режим демо.

`test_consultation_design.cjs` проверяет все перечисленные состояния и делает их скриншоты; `test_consultation_ui.cjs` проверяет реальные сохранение/изменение/перезагрузку и просмотр архива. `response_metadata_test.go` проверяет metadata нескольких ответов после перезапуска. Снимки повторной приёмки: `reports/consultation-ui-v2/`.

Более поздняя живая проверка: `reports/web-demo-readiness-20261112.json` (один ответ за 59 с после изменения веб-адаптера). Новая проверка передачи в Git описана в `reports/team-code-publish-20261112.json`; она не повторяет оценку качества модели.
