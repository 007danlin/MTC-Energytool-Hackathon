## Решение по конкурсному качеству

Лучший подтверждённый результат остаётся **N2 docs — 69.912**. Нового платформенного результата нет. Ни N6, ни N7 пока не рекомендую как доказанное улучшение для расходования ограниченной попытки. Платформенных отправок не делалось; остаток командных попыток неизвестен. Цель 75+ не достигнута и не объявляется достигнутой.

**N6 local context cap:** 47 технических проверок, 17 целевых HTTP-сценариев и 209 healthy запросов с точным совпадением с N2. Две реальные пары после искусственного отказа дали одинаковые ответы — две ничьи. Пятый запрос был прерван при критическом давлении памяти. Исправляемая ветка действительно существует, но её частота на платформе и выигрыш качества не установлены. На известных 123 вопросах запросы с 4096 output помещаются в 32k; synthetic overflow не доказывает типичность проблемы. При повсеместном overflow найден риск дополнительных 206 HTTP-отказов на 209 строк. Итоги: `live-diagnostics-v1/final-summary.json`, `runtime-probe/final-healthy209-proof.json`.

**N7 focus order:** из точного N2 изменён только retrieval.py. Четыре наиболее релевантных допускающих перестановку фрагмента перемещаются в начало, остальной контекст сохраняется. Никаких новых моделей, фактов, вопросов или ответов в runtime нет. Явные ссылки «см. выше/ниже» защищены; исходный непротестированный вариант без защиты сохранён как rejected-v0. Воспроизводимый ZIP прошёл 47 проверок, сохранность источников на 202 известных сценариях и 64 проверки уменьшения контекста. Эти проверки не являются качеством модели.

В реальной серии N7 завершена одна из четырёх заранее выбранных пар. Оба ответа правильно отвергли обещание запустить станцию 400 кВт за типовые два месяца. Слепой по названиям проверяющий слегка предпочёл N7 за точность условия и более нейтральное уточнение размещения; существенной ошибки у N2 не найдено. Одна близкая пара не подтверждает общий прирост. Третий HTTP-запрос прерван, остальные пары не оценивались. Начальный review был исправлен после чтения полного официального solar.md: отсутствие числа в краткой rubric не означало отсутствие числа в базе. Обе версии review сохранены. `rerank-order-v1/DECISION.md` содержит полное обоснование.

## Реранкер

B/B2 работали с выключенным reranker: их плохой платформенный результат не доказывает вред реранкинга. Старый опыт Qwen3-Reranker-0.6B на CPU не завершил проверку качества и был медленным. Готового локального cross-encoder в проверенных путях не найдено; BGE-M3 — bi-encoder, другая модель. Отдельный neural reranker пока не добавлен: не установлены выигрыш качества, доступность реального endpoint и способ соблюсти время/упаковку. N7 проверяет только порядок уже выбранных блоков. Первичная [карточка нейронной модели](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B). История и ограничения: `RERANKER_REVIEW.md`.

## Реальная модель и ресурсы

Локально запущена mlx-community/Qwen3.8-27B-4bit, revision b935172e4bb5dcd0543774a34748fb92422e3027; веса и окружение проверены и сохранены отдельно. Это локальное 4bit исполнение, а не точное воспроизведение скрытого провайдера. В N7 реальные первые HTTP payloads имеют одинаковые kwargs, system, диалог и состав текстовых блоков; отличается только порядок.

N2/hold01: HTTP200, stop, 19357 input и 1048 completion tokens. N7/hold01: HTTP200, stop, 836 completion tokens. Сравнивать их времена как ускорение нельзя: различались prefix cache и сон хоста. Первый HTTP занял 647.54с активных часов, но 1658.81с по wall clock; разрыв подтверждён журналами Sleep/Wake. Это не задержка между запросами.

Серия N7 остановлена при зарегистрированном thermal state critical и повторном Thermal Emergency Sleep. Физическая температура не измерялась, единоличная причинность модели не доказана. На N7 не было обнаружено чужой тяжёлой модели или memory pressure critical. Остановлены только наши процессы, порт18765 свободен; итоговое состояние thermal nominal, memory pressure normal. Повторный тяжёлый запуск не выполнялся. `model-session/thermal-interrupted-resource-summary.json` внутри N7 содержит точные события.

## Веб-отладка и требования

По сохранённым первичным материалам организаторов debug должен отдельно показывать время и документы/фрагменты ответа. Исправлены: нулевое время при транспортном сбое ML, потеря диагностики в истории, просмотр источников конкретного архивного ответа. Теперь найдённый контекст отделён от выбранных цитат; проверка происхождения цитаты не объявляется проверкой каждого утверждения. Старые записи без данных показывают отсутствие метаданных; доступная диагностика последнего ответа восстанавливается только при совпадении текста и статуса.

Устранено требование полного ФИО и компании для готовности заявки. Телефон ИЛИ email проходят через извлечение, форму, Go API, хранение, карточку и экспорт. Прежние телефонные заявки совместимы. Исправлены подмена email усечённой цитатой и потеря исходного написания адреса. Область синтаксиса — одиночный ASCII mailbox, без проверки доставляемости или отправки письма. Пройдены 30 целевых Python-тестов, Go/race, HTTP с перезапуском хранилища, браузер через настоящий Go API и регрессии дизайна/карточки/очереди. Результаты и хеши 31 изменённого файла: `web-debug-audit/validation.json`; карта требований: `web-debug-audit/ORGANIZER_COMPLIANCE.md`. Патч применён в чистой копии и точно воспроизвёл все 36 сохраняемых файлов, включая 5 исходных пользовательских файлов без новых изменений.

Организаторский ориентир 5–7с на ответ реальной модели не подтверждён: HTTP-тесты с имитатором проверяют контракт, а не живую скорость. Сохранённый live замер12ноября59с тоже не соответствует этому ориентиру. Новые изменения ещё не развёрнуты в работающем Go/Python стенде: его чужие процессы не перезапускались. Авторизации владельцев истории в существующем backend нет; конфигурация доступна на loopback и не заявляется многопользовательским размещением.

Подробная карта с первоисточниками и статусами — `web-debug-audit/ORGANIZER_COMPLIANCE.md`. Правила проверены по предоставленному пакету; более новые изменения закрытого канала после сохранённого Q&A не подтверждены. Пользовательские изменения CTA/вёрстки сохранены, baseline diff лежит в web-debug-audit/baseline.
