# E2: сохранение контекста A2, 11 ноября 2026

**E2 отклонён. A2 с подтверждённым платформенным баллом 55.969 остаётся рабочей версией.** На 41 открытом случае E2 дал 2 улучшения, 3 ухудшения и 36 ничьих по локальной проверке. Обнаружены две новые существенные ошибки. Holdout не открывался, попытки платформы не использованы, новый ZIP для отправки не выпускался.

E2 сохраняет весь список исходных фрагментов A2, их текст и порядок. Затем добавляет до 4 новых разделов из первых 12 результатов BGE-M3 вместе с полными ограничениями соответствующего продукта. Дополнительный текст ограничен 6000 символами и свободным местом в исходном лимите 32000. Промпт, запрос поиска, база и параметры генерации не изменялись. Готовый индекс из E1 использован повторно; веса модели в ZIP не входят.

Это свойство подтверждено 105 проверками на 35 запросах при лимитах 4000/32000/90000 символов и проверкой всех 41 фактических контекстов реального прогона: исходный контекст A2 оставался неизменным префиксом. В среднем добавлено 2802 символа, максимум 5573. Таким образом, ошибки E2 возникли при сохранённых исходных сведениях; само увеличение контекста не обеспечило улучшение генерации.

Улучшения: `n04` — проверка пригодности существующих приборов без прежней безусловной замены; `17` — более предметный, хотя всё ещё неполный ответ о проверке счёта. Первоначальный выигрыш в `n11` снят при консервативном разборе: вместо повторного вопроса о ресурсе E2 стал требовать тип прибора, хотя OCR не зависит от типа/модели. Первичная и уточнённая оценки сохранены отдельно.

Ухудшения: `check2` — не пояснено прямо, что сервис сам не выполняет выездные проверки; `check3` — выдуман верхний предел точности распознавания воды «не более 95%», тогда как база задаёт только показатель «более 90%»; `q02` — обещана не выполняемая отправка обращения. Последние два случая — новые существенные ошибки на месте более качественных ответов A2. Их нельзя скрывать общим числом ошибок: у обоих вариантов по 7 существенно ошибочных ответов, но они возникли в разных случаях. Хороших ответов по локальной оценке: A2 — 28, E2 — 27.

Выполнена 41 новая генерация на установленной Qwen3-VL-30B-A3B Instruct Q4_K_M: контекст 16384, seed 42, температура 0, max_tokens 2048, один поток. Контрольные ответы A2 повторно не генерировались: у всех 41 запроса подтверждено точное совпадение сериализованного тела API-запроса с сохранёнными наблюдениями. Проверка выполнена автором изменений по полной базе; метки вариантов перемешаны, но прежние ответы могли быть узнаваемы. Это не независимый эксперимент и не прогноз балла Qwen3.8-27B платформы.

В обоих прогонах E2 действительно работал гибрид: 43 успешных вызова эмбеддингов и 41 успешный вызов генерации, без обрезанных ответов, все CSV корректны. Время двух запусков: 450,66 и 782,97 секунды. Суммарное время обработки 41 случая: 1233,138 секунды у E2 против 1216,129 у сохранённых запусков A2. Это разные запуски и состояния кеша, поэтому причинный процент изменения скорости не заявляется. 41 вопрос проверялся двумя партиями, а не одним процессом в 20-минутном лимите. Скорость настоящего API платформы не проверена. Вызовы эмбеддингов заняли суммарно 33,516 с, среднее 0,779 с; максимальный RSS процесса сабмита около 49,5 МБ, без локальных серверов моделей.

Пройдена 21 автоматическая проверка. Точный ZIP запущен в Docker Python 3.9.25 на Linux ARM64, 512 МБ и 2 CPU без внешней сети: совместимые векторы, несовместимость и HTTP503. При отказе использованы состав и порядок источников A2. Docker воспроизводил сохранённые векторы и mock-генерацию; проверка качества выше использовала реальные модели. Совместимость с API эмбеддингов платформы остаётся неподтверждённой.

Тестовая сборка сохранена локально: `reports/private/preserving-hybrid-e2-20261111/candidate.zip`, 939911 байт, SHA256 `97bbaed99f0228769209823a81fbdc4aea69c639c641eb329951e43f053bd636`. Она не перенесена в каталог готовых сабмитов. Все ответы, рубрики, протоколы, скрипты и исходники сохранены в каталоге эксперимента; [машиночитаемый итог](../reports/preserving-hybrid-e2-comparison-20261111.json) содержит измерения и ссылки на доказательства.

При аудите контрольных ответов также исправлена атрибуция ошибки `n04` в прежнем отчёте E1: условие обязательной замены относилось к A2, а перенос проверки передачи данных поставщику — к E1. Оригинальный отчёт сохранён в частном каталоге E2, оценки и результаты E1 не изменены. После просьбы пользователя продолжить начата отдельная проверка избирательного E3; исходники E2 остаются заморожены.

**Уточнение после аудита причин:** прежняя формулировка «полные ограничения продукта» не подтверждена: эвристика выбирает лишь часть заголовков и пропускает отдельные ограничения целевой аудитории. Исходные секции сохранялись целиком, но полнота всех нужных ограничений не гарантировалась. [Доказательства и новый диагностический прогон](root-cause-audit-20261111.md).
