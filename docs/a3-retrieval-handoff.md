## 2. Вариант B — `hybrid_retrieval.py`

- Контракт прежний: `search(query, top_k) -> list[Fragment]`, `source_id` как в A2.
- Ранжирование: BM25 A2 (top-k) + bge-m3 (пул 30) через RRF (k=60). Запрос для эмбеддинга — последняя
  реплика (вес 0.65) и последняя реплика с историей (0.35); ответы ассистента фактами объекта не считаются.
- После top-k добавляются ограничения **только 1–2 продуктов, лидирующих в выдаче**: «Чего утверждать нельзя»,
  «Что мы не делаем», «Не подходит…», «Важное ограничение…», «Что нужно от клиента», раздел продукта в
  `02-product-scope-and-limits`; числа из `01-numbers-and-indicators` — только для числового вопроса.
- Эмбеддинги — **при запуске** через `POST {LLM_BASE_URL}/embeddings` (`EMB_MODEL`, по умолчанию `baai/bge-m3`
  из примера организаторов). Индекс в ZIP не кладём: векторы документов и запросов всегда от одной модели,
  доказывать совпадение версии/pooling не нужно.
- Fallback на A2, наблюдаемый в stderr (`inputs_ready.retrieval`) и итоговом stdout (`retrieval`):
  ошибка при старте → `lexical_fallback`; 3 подряд сбоя на вопросах → предохранитель, дальше A2;
  `RETRIEVAL_MODE=a2` → принудительно A2. Таймаут запроса эмбеддинга вопроса 8 с, одна попытка.
- Только стандартная библиотека, `requirements.txt` не меняется.

Diff относительно A2: `solution.py` (импорт `create_retriever`, 2 строки диагностики),
`tools/build_submission.py` (+`hybrid_retrieval.py` в ZIP). `consultant.py`, `prompts.py`, `settings.py` не тронуты.

## 5. Что не сделано и почему

- **Вариант C (реранкер)**: Qwen3-Reranker-0.6B на CPU — больше 2 минут на вопрос даже с пулом 12;
  прогон 93 вопросов — часы. Не измерен → не включён (`HYBRID_RERANK=1` оставлен выключенным).
- **Порог уверенности**: похожесть bge-m3 у вопросов вне базы (0.41–0.63) перекрывается с обычными (от 0.51) —
  порог не отделяет. Не внедряли.
- **Сравнение ответов на Qwen 30B** — нужен локальный сервер Даниэля:
  `python tools/compare_retrievers.py --variants A,B --split dev --local-embeddings --output reports/private/a3-compare`
  → `answers.json` (ответы, источники, время, ошибки API) + `blind_pairs.json` (стороны перемешаны, ключ отдельно).
- **Новые финальные вопросы** — пишет Артём после фиксации параметров, по `eval/final_questions_template.md`.
