# Проверка готового индекса: E1, 11 ноября 2026

Рабочая версия остаётся **A2 с результатом 55.969**. Полученный от пользователя результат **G — 51.729**, ниже A2 на **4.240** балла; сохранён отдельно в [записи платформенного результата](../reports/platform-result-g-20261111.json). Ни A2, ни G, ни V3, ни результаты прежних экспериментов не изменены. Все девять корневых файлов рабочей сборки по-прежнему побайтно совпадают с A2.

Q&A №32 разрешает готовые индексы в корне ZIP рядом с `solution.py`. Это учтено в отдельном эксперименте **E1**. Его технические проверки пройдены, но улучшение качества относительно A2 не подтверждено. Продвигать E1 в рабочую версию и расходовать на него попытку сейчас не рекомендовано.

**Состав и совместимость.** Предварительно рассчитаны векторы 234 полных разделов базы на официальной BAAI/bge-m3, revision `5617a9f61b028005a4858fdac845db406aefb181`. Использованы CLS, L2-нормализация, float32 и 1024 измерения без префикса; максимальная длина документа — 660 токенов, усечения не было. Модель допускает 8192 токена и не требует инструкционного префикса запроса: [официальная карточка BGE-M3](https://huggingface.co/BAAI/bge-m3).

В корне ZIP находятся 12 файлов: девять файлов A2, новый модуль поиска и два файла индекса. Из прежних файлов изменён только экспериментальный `solution.py`: подключение поиска и диагностический вывод. Веса модели, база, вопросы и ответы в ZIP не входят. Дополнительные зависимости при запуске не нужны. Архив занимает **939 684 байта — 0,94 МБ**, значительно меньше 128 МБ.

При загрузке проверяются формат, модель, SHA векторов и точное соответствие ID/содержимого всех разделов поступившей базы. Три контрольных текста, включая длинный текст более 512 токенов, проверяют совместимость запросных эмбеддингов через `/embeddings`; минимум косинуса — 0.999. На реальном локальном BGE-M3 косинусы совпали с 1 с погрешностью округления. В запросах используются общий адрес/ключ генерации и `EMB_MODEL` с умолчанием `BAAI/bge-m3`.

**Реальный API платформы недоступен**, поэтому совпадение его кодировщика с локальным не подтверждено. Контрольные векторы — защитная эмпирическая проверка, не доказательство совпадения на всех текстах. При несовпадении модели/базы, повреждении индекса, несовместимых векторах или ошибке API решение использует исходный поиск A2. После первой ошибки векторная ветка отключается до конца запуска. Длинный запрос направляется в исходный поиск без усечения.

**Сравнение поиска.** На 35 уже открытых случаях сопоставлены A2/G (у них одинаковый поиск), чистый плотный поиск и фиксированный гибрид RRF60 с равными весами. Использованы те же полные разделы, 12 основных фрагментов и предел 32000 символов контекста. Веса и параметры после просмотра результатов не подбирались; holdout не открывался.

Это диагностические метрики источников, не оценки ответов. В `n04` гибрид добавил раздел ограничений, но не основные сведения о совместимости. В `12`, `15`, `17` потеряны отдельные группы источников; часть фактов повторяется в других разделах, поэтому такая потеря не всегда ухудшает ответ. Например, порог мощности в ответе `12` сохранился. Более высокий MRR не означает автоматически более качественный ответ.

**Реальная генерация.** Точный ZIP E1 проверен на установленной Qwen3-VL-30B-A3B Instruct Q4_K_M: контекст 16384, seed42, температура0, 2048 выходных токенов, один поток. Проверены все 12 открытых dev-вопросов и три случая с потерями источников; состав зафиксирован до генерации. Получены 15/15 ответов, CSV корректен, 15 вызовов генерации и 16 вызовов эмбеддингов прошли без HTTP-ошибок и обрезания ответов. Итоговый режим — гибрид, резервный поиск не подменял эксперимент.

Сравнение с сохранёнными ответами A2: **1 победа, 13 ничьих, 1 ухудшение**. Оба варианта получили по 10 хороших, 3 неполных и 2 существенно ошибочных ответа по локальной оценке. E1 лучше направляет ответ `17` на проверку счёта, но он остаётся неполным. В `15` возникла новая существенная ошибка: вместо проверки состава и совместимости приборов для учёта по арендаторам предлагается сразу настраивать Telegram-бота. Сценарий `n04` надёжно не исправлен: в A2 есть неподтверждённое обобщение об обязательной замене существующих приборов, а E1 переносит проверку передачи данных поставщику в сценарий внутренней платформы. Атрибуция этих двух ошибок уточнена 11 ноября по исходным CSV; оценки обеих сторон и итог сравнения не изменены.

Оценка выполнена автором эксперимента по полной базе с перемешанными метками A/B, а не независимым судьёй. Исторические ответы A2 использованы повторно с сохранённым происхождением; это не новый независимый прогон. Выборка мала, известна разработке и включает специально выбранные проблемные случаи. Выводы не являются прогнозом платформенного балла; локальная Qwen отличается от Qwen3.8-27B платформы.

**Скорость и ресурсы.** Построение векторов документов на локальном MPS заняло 21,917 с один раз; загрузка готового индекса — 0,0246 с. Отдельное кодирование запроса без одновременно работающей Qwen: среднее 0,106 с. Первый запрос с контрольной проверкой через локальный API — 2,491 с. В совместном прогоне 16 вызовов эмбеддингов заняли суммарно 11,802 с, в среднем 0,738 с, максимум 2,157 с.

Весь прогон E1 занял 300,81 с. Сумма времён обработки тех же 15 случаев: E1 — 300,588 с, сохранённый A2 — 374,256 с; на общих 12 dev-случаях — 232,125 против 259,123 с. Это наблюдения разных запусков с разными состояниями кеша и нагрузкой GPU, а не доказанный процент ускорения. Максимальный RSS процесса сабмита — около 49,2 МБ, без локальных серверов моделей. Задержки и скорость настоящего API платформы не измерены.

**Техническая приёмка.** 15 автоматических проверок загрузки, формата ответа API, нормализации, срока выполнения и возврата к A2 пройдены. Точный ZIP запущен в Docker Python3.9.25, Linux ARM64, с 2 CPU и 512 МБ, без внешней сети. В трёх сценариях — совместимый индекс, несовместимые векторы, HTTP503 — получен корректный CSV из четырёх строк; состав и порядок источников соответствуют ожидаемому режиму. Docker использовал воспроизведение сохранённых настоящих векторов и mock-генерацию: он подтверждает протокол, а качество проверено отдельным реальным прогоном выше. Docker на архитектуре платформы и её модельный API не проверены.
