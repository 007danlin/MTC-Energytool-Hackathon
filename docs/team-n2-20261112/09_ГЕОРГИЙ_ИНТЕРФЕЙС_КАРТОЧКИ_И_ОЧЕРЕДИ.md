# Георгию: интерфейс карточки и очереди заявок

12 ноября 2026. Самодостаточное задание для передачи Георгию.

В `main` уже есть бизнес-логика карточки и обработки заявок. База этой передачи — коммит `147b862`; перед работой обнови ветку до свежего `main`. Игорь подключает модуль к API и хранению. Поля, действия и ошибки описаны в [контракте v1.2](https://github.com/007danlin/MTC-Energytool-Hackathon/blob/main/docs/business-contract.md).

Твоя следующая задача — подключить интерфейс:

1. Существующая форма клиента сохраняет заявку через API; после успеха интерфейс показывает фактически сохранённые данные.
2. Сделать очередь заявок с фильтром по статусу и переходом в карточку. Предусмотреть загрузку, пустой список и ошибку.
3. В карточке показать задачу, контакты, известные параметры, продукты, неизвестное и следующий шаг. Различать «подтверждено / предположение / неизвестно», актуальную мощность и прежние значения.
4. Подключить действия менеджера: взять в работу, принять, запросить уточнение, отклонить, открыть повторно. Для нужных переходов запрашивать причину.
5. Подключить правки и TXT/JSON-выгрузку. При конфликте версии перечитать карточку и сообщить об изменении; повторный клик не должен создавать дубли. При повторе той же команды сохранять её `client_request_id`; изменённая команда получает новый ID.
6. Демо-признак и метрики брать из API. `accepted` показывать как принятие менеджером в работу; отправку в CRM пока не заявлять.

**Совместная приёмка с Игорем:** вопрос → подтверждение заявки → очередь → карточка → решение менеджера → обновление метрик → перезагрузка.

Проверить совпадение данных карточки и экспортов, сохранность результата после перезапуска сервера, обработку конфликта версии и доступность сохранённой заявки при недоступной модели.

Цикл «неизвестный вопрос → специалист → пополнение базы» идёт следующим этапом по отдельному дополнению к ТЗ. Его бизнес-модуль готовит Артём, API и доставку подключает Игорь; поля для экрана специалиста они передадут отдельно.
