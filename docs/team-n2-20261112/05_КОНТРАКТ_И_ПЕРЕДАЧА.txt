СОГЛАСОВАНИЕ ИНТЕРФЕЙСОВ И ПЕРЕДАЧА КОЛЛЕГАМ
Это предложение границ работы, не утверждение, что новые API уже реализованы.

ДЕЙСТВУЕТ СЕЙЧАС
POST /api/v1/sessions; GET /api/v1/sessions; GET /api/v1/sessions/{id}; POST .../{id}/messages; GET .../{id}/messages; POST .../{id}/close; GET .../{id}/lead; POST .../{id}/application.
Заявка: full_name, phone, company, summary, saved_at. Ответ консультанта: answer, status, sources, elapsed_ms, lead, lead_ready, summary, debug, schema_version. В истории response metadata привязаны к сообщению.
Уже реализованные маршруты и поля подтверждены чтением текущих backend/README.md и backend/internal/domain/models.go; актуальная ветка команды может отличаться.

КОНТРАКТНАЯ ВСТРЕЧА: ДО 13.11 12:00 МСК (ВНУТРЕННИЙ ОРИЕНТИР)
Игорь фиксирует общий envelope/error/request_id и семантику повторов.
Артём предлагает добавочный application_id/version, подтверждённые факты/неизвестное/следующий шаг, состояния обработки и события. Отдаёт минимальные JSON-примеры, не требует переписать работающую форму.
Георгий проверяет, что по полям можно однозначно показать состояния и подтверждение, и согласует размер карточки/очереди.
Если расширение нужно для P1, не блокировать P0 ожиданием полной схемы аналитики. Зафиксировать совместимый минимум и затем расширять.

ПРЕДЛАГАЕМЫЕ НОВЫЕ ВОЗМОЖНОСТИ API (ИМЕНА СОГЛАСОВАТЬ)
Список заявок с фильтром → карточка по ID → изменение статуса/версии с причиной → человекочитаемый экспорт → сводка метрик за период. Это логические операции; REST-пути/структуру выбирают Игорь и Артём.
Транспорт/хранилище/регистрация роутов — Игорь. Правила карточки/переходов/метрик — Артём. Представление и пользовательские действия — Георгий. Игорь не реализует параллельно бизнес-формулы; Артём не переписывает весь HTTP-сервер.

ПЕРЕДАЧА КОДА
Каждый отдаёт небольшой законченный коммит/PR, описание поведения, проверку, ограничения и примеры запросов/ответов. Перед слиянием Игорь прогоняет общую цепочку с Георгием. Неработающую «будущую» кнопку не включать как готовую функцию.
Исходная версия для работы — свежий origin/main: там опубликованы веб-код, тесты, ресурсы сайта и дизайн. prototype-source-snapshot.zip в ранее переданном пакете — исторический неполный снимок; не перезаписывать им актуальную ветку. Перед работой git fetch origin, затем обновить свою ветку согласованным способом; чистый main можно обновить через git pull --ff-only.
В winner/ — точный конкурсный N2 и отчёт о результате. Они помогают воспроизводимости и проверке версии, а не требуют заменять текущий web runtime простым копированием solution.py.
