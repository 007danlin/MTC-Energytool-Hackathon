Что изменилось
Основа — точные файлы A2. Изменены только импорты в solution.py и добавлен verified_conditions.py.
Промпт, API-клиент, парсер диалога, базовый поиск, генерация и настройки остались A2.
К исходным фрагментам в прежнем порядке добавляются не более двух явно отмеченных вычисленных условий с полным исходным пунктом базы. Пороговые значения читаются из предоставленной платформой базы, а не из тестовых ответов. При неоднозначных числах условие не добавляется.
Проверяются диапазон мощности солнечной генерации, пороги ОРЭМ/ценовых категорий, остаточный срок кровли, длительность архива потерь и различие экономического ориентира и запрета. Мощность из истории берётся только из реплик пользователя с проверкой смены объекта/типа мощности. Значения из ответов ассистента не становятся фактами клиента.
Нет нового вызова модели, эмбеддингов, индекса, веб-бэкенда или внешних зависимостей. На вопрос — один обычный запрос генерации, как у A2. TOP_K учитывается как в A2, без принудительного повышения заданного значения до12. База и оценочные вопросы в ZIP не включены.

Модель: Qwen3-VL-30B-A3B-Instruct, Q4_K_M, alias energytool-qwen-local-eval:20261110. Это другая модель, чем Qwen3.8-27B на платформе.
Оценка выполнена автором изменений по базе и заранее указанным обязательным фактам; она не слепая и не независимая. Увеличение длины ответа не считалось улучшением.

На широком наборе исправлен диалог о700кВт: A2 разрешал II категорию вопреки порогу, A10 однозначно запрещает и указывает III–VI.

Для93 сохранённых ответов оригинальные HTTP-хеши не записывались: воспроизведение подтверждено неизменным кодом, базой, вопросами, настройками, порядком источников и длиной контекста. Для23 целевых случаев и нового набора есть полные хеши запросов. Готовые идентичные генерации не повторялись.
Всего в A10 выполнены52 новых вызова, включая отклонённые промежуточные варианты. Изменения после проверки пересчитывались только для затронутых запросов. Отдельно сохранены23 неудачные попытки редактирования ответа в A9; этот подход отклонён. Ошибок API и обрывов в завершённых локальных генерациях не было.

Промежуточные регрессии и ограничения
Дополнительное правило о нижних границах точности распознавания не помогло: модель продолжала придумывать верхний предел. Правило исключено, результат сохранён.
В r4 фраза о документах вызвала неверное указание документа для текущей ценовой категории. В r5 эта фраза удалена; четыре изменившихся запроса перепроверены, регрессия исчезла. Поэтому новый набор после этого исправления уже нельзя считать нетронутым holdout.
В финальных изменённых ответах новых существенных или новых мелких ошибок в этой проверке не обнаружено. Это не доказательство отсутствия всех ошибок. Остаются, например, некорректное общее согласие при отсутствии разбивки архива на день/ночь, пропуск ограничения для бизнес-центров без производственной нагрузки, ошибки интерпретации точности распознавания. Не все найденные проблемы удалось надёжно исправить без ухудшений.

Техническая готовность
Docker-образ собран из точного ZIP на Python3.9. Пройдены80 тестов:65 существующих и15 новых проверок числовых условий/истории. Пять сценариев контейнера без внешней сети при2CPU и512МБ: обычный запуск, повтор429/503, ошибка401, обрыв генерации и короткий дедлайн. Во всех сохранён валидный CSV со всеми123 идентификаторами. В обычном режиме123 ответа и123 вызова; при429/503125 вызовов. Технические ответы при сбоях не маркируются успешными.
Это проверка протокола на тестовом сервере, не живого API платформы. Реальная Qwen использовалась отдельно для качества. Готовый ZIP значительно меньше лимита128МБ. В корне рабочей папки все девять модулей A2 остались побайтно прежними.

Решение
A10 готов для одной экспериментальной загрузки: локальное точечное улучшение подтверждено описанными проверками. Глобальное превосходство над A2 на скрытой выборке и результат выше60 не подтверждены. A2 остаётся рабочей версией до фактического более высокого балла. Автоматическая загрузка на платформу не выполнялась.
