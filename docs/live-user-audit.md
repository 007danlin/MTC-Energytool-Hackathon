## Исправления по наблюдениям

- Обычное прерывание больше не выглядит технической ошибкой. При возврате экран сообщает о проверке готовности, а не требует ручного обновления.
- Неизменившийся фоновый опрос не пересоздаёт кнопки и не сбрасывает клавиатурный фокус.
- Автоматическое резюме заявки обновляется при повторном открытии; новые неподтверждённые моделью уточнения передаются как слова клиента. Ручное описание сохраняется и остаётся редактируемым после reload.
- Черновики в истории имеют названия по введённому тексту и отметку «ещё не отправлен». Пустая форма не предлагает просмотр несуществующей переписки.
- Email-заявка не получает выдуманное пожелание о телефонном звонке. Явно заданные менеджером сведения не удаляются нормализацией.
- Попытка изменить принятую/отклонённую заявку возвращает понятный `409 application_closed`, сохраняет исходные данные и объясняет путь продолжения. Мобильное окно прокручивается к сообщению об ошибке.
- Ответ специалиста сохраняется и в закрытом диалоге. Ранее потерянные в истории доставленные ответы восстанавливаются без дублей при запуске; возобновление диалога сохраняет подпись специалиста.

Проверки интерфейса дополнены воспроизводимыми регрессиями `test_application_summary_recovery.cjs`, `test_wait_recovery.cjs`, `test_navigation_recovery.cjs`; серверные случаи покрыты Go-тестами. Полный HTTP-стек и аварийное восстановление проверены отдельно через `test_web_stack.py` и `test_wait_recovery_stack.py`.

## Ошибки содержания, обнаруженные живыми вопросами

Первый ответ про существующие счётчики смешал сведения для платформы учёта и данные для поиска коммерческих потерь. После уточнения системных правил повторный ответ запросил тип/модель для проверки и больше не переносил требования к дневному/ночному потреблению на подключение приборов. При этом одна инструкция не исключила безусловное начало «Да».

В альтернативной беседе модель предложила солнечную станцию только из-за мощности ниже порога другого решения; затем перенесла 670 кВт из ценовых категорий на оптовый рынок и повторно спросила уже названный тип объекта — кафе. Происхождение цитаты само по себе не подтверждает такой вывод. Эти примеры сохранены в `variations/result.json`; успешный статус браузерного сценария означает работоспособность переходов, а не правильность этих ответов.

Исправления включают инструкции текущего хода и узкие программные проверки наблюдавшихся ошибок:

- Первый общий запрос без данных об объекте получает вопрос об объекте. Необоснованный подбор продукта после генерации заменяется уточнением.
- Кафе, кофейня и ресторан распознаются как уже указанный объект; вопрос о его типе не повторяется.
- Для подключения существующих счётчиков требуется подтверждение всех названных моделей в источниках. При его отсутствии ответ предлагает проверку специалистом, не обещает совместимость и не объявляет замену обязательной.
- Если клиент прямо сказал, что модель счётчика неизвестна, тот же вопрос не задаётся заново: можно сообщить сведения позже или обратиться к специалисту.
- Перенос условия 670 кВт из ценовых категорий на оптовый рынок отклоняется с одной попыткой исправления; повторная ошибка остаётся видимым техническим результатом с возможностью продолжить или оформить заявку.
- При явной просьбе первых действий по росту счёта известного объекта из контекста убираются источники, принадлежащие продукту поиска коммерческих потерь. Если клиент спрашивал о потерях, хищениях или аномалиях, эти источники сохраняются. Общая диагностика остаётся доступной; ответ продолжает генерироваться моделью по источникам.
- Удалённые необоснованные рекомендации не остаются в резюме и карточке задачи.

Повтор `content-final/` подтвердил уточнение объекта, отсутствие повторного вопроса о кафе, устранение ошибочного порога и осторожный ответ о неизвестных счётчиках. Первый ответ был получен после возврата в настоящую сессию `cab095ba-f5f4-4e61-953a-d350491ea435`: начальный браузерный прогон `content-fixed/` остановился по таймеру при большом скачке общего времени. Сервер сохранил результат и измерил 138,3 с обработки; повторный вход показал ответ и позволил отправить следующий вопрос. Это сохранённый неуспешный прогон, а не скрытая замена его результата.

Дополнительное чтение ответа про кафе выявило оставшееся смешение требований: полезный совет сравнить объём/цену/мощность сопровождался требованием годового дневного/ночного архива из продукта поиска коммерческих потерь. Автоматические проверки `content-final` на тот момент эту ошибку не проверяли; их успешный статус её не опровергает. Добавлена отдельная проверка `test_live_bill_diagnosis.cjs`, а общий сценарий усилен тем же условием.

Это ограниченные проверки конкретных классов ошибок, а не гарантия правильности произвольных ответов модели. Поле `debug.routing` отдельно отмечает программную корректировку после настоящего вызова модели; такие ответы не выдаются за улучшенную свободную генерацию. Новые регрессии: `tests/test_web_turn_boundaries.py`.
