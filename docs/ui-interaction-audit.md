# Аудит взаимодействий EnergyTool — 15 ноября 2026

Проверены консультация, карточка задачи, источники, история и возврат, формы заявки, очередь заявок, кабинет специалиста и мобильная версия. Исправления установлены на локальном Docker-стенде `http://127.0.0.1:8768`; тома с историей и заявками сохранены.

## Найденные и исправленные проблемы

| Проблема | Поведение после исправления |
|---|---|
| После прерывания ожидания оставались заблокированный ввод и ручное обновление | Явный экран восстановления, автоматическая проверка раз в 3 секунды, редактируемый черновик, продолжение ожидания и обращение оператору. Автоматического повторного POST нет |
| При долгом ответе нельзя было уйти к оператору | После 20 секунд появляется «Позвать оператора». Кнопка также доступна после прерывания и технической ошибки. Открывается проверяемая заявка с исходным вопросом |
| Генерация удерживала блокировку сессии и задерживала заявку/выход | Общая блокировка отпускается на время ML. Заявка сохраняется сразу; поздний ответ сохраняет внесённые изменения |
| После аварийного перезапуска оставался последний пользовательский ход без ответа | При чтении сессии один раз сохраняется технический результат с возможностью повторить запрос; вопрос и история сохраняются |
| Потеря ответа могла привести к повторному пользовательскому ходу | Запросы имеют `client_request_id`, незавершённое состояние сохраняется до вызова модели. Повтор использует прежний ID; повтор после зафиксированной технической ошибки — новый |
| История позволяла лишь читать, а выход закрывал сессию | «Продолжить этот диалог» работает для активных и ранее закрытых диалогов. Новый диалог сохраняет старый, выход на сайт позволяет вернуться в тот же разговор |
| С проверки заявки и отказа от контакта не было свободного возврата | Добавлены явные кнопки возврата в консультацию. Черновики сообщения и формы сохраняются отдельно для каждой сессии в текущей вкладке |
| Поздний фоновый GET мог затереть только что сохранённую заявку в интерфейсе | Устаревшие ответы отбрасываются; открытая форма не перерисовывается фоновым опросом |
| Специалист терял набранный ответ при переходе в работу или ошибке отправки | Черновик сохраняется при обновлении, повтор команды сохраняет идентификаторы, ошибка обновления списка не обрывает отправку |

Дополнительно:

- 116 Python unit-тестов: `python3 -m unittest discover -s tests -q`.
- Go: `go test -race ./...` и `go vet ./...`, включая новые проверки конкурентного сохранения, восстановления и HTTP `/resume`.
- `test_web_stack.py`: настоящий веб-прокси → Go → Python → тестовый HTTP API модели; история, изоляция, заявки, перезапуск и доставка ответа специалиста без дубля.

- Формы, контакты и публикация/отзыв знаний дополнительно пройдены в браузере с настоящим Go API и отдельным временным хранилищем. Рабочая база знаний не использовалась для тестовой публикации.
- Синтаксис изменённого JS и `git diff --check` прошли.

## Границы результата

Аудит подтверждает перечисленные переходы и восстановление приложения. Контролируемые ответы позволяют воспроизводить ошибки и длительное ожидание; качество и скорость живой языковой модели этим прогоном не измерялись.

После этого проведён отдельный аудит с настоящей моделью: [живой пользовательский прогон](live-user-audit.md). Он включает реальные прерывания и возвраты, оформление заявки во время генерации, альтернативные вопросы и исправления обнаруженных ошибок содержания.

«Позвать оператора» сохраняет заявку в существующую очередь после проверки контактов. Мгновенное подключение сотрудника, внешняя CRM, реальный звонок и отправка email не подключены. Авторизация МТС и оформление заказов на скопированной витрине также остаются демонстрационными ограничениями, описанными в README.

Черновики хранятся в `sessionStorage` текущей вкладки; история и подтверждённые заявки — на сервере. Закрытие вкладки может удалить несохранённую форму, поэтому важную заявку нужно подтвердить.
