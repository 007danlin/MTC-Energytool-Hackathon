АВТОМАТИЧЕСКАЯ ОЦЕНКА
Два предъявления: baseline/команда и команда/baseline. Оценки раунда: 0, 0.25,
0.5, 0.75, 1. Для вопроса s_i=(r_i1+r_i2)/2.
MatchRate = mean(s_i) по вопросам, успешно оценённым судьёй.
WinRate = W/(W+L), W: s_i>0.5; L: s_i<0.5. Ничьи исключаются.
Если все сравнения — ничьи, WinRate=0.5.
Score = 0.7*MatchRate + 0.3*WinRate, диапазон формулы 0..1.
Выгруженные числа 55.969 и т.п. — отображаемые баллы личного кабинета, не доля
правильных ответов. Формулу и шкалу кабинета не смешивать.
Baseline организаторов скрыт и не является нашим A2. Golden тоже скрыт.
Генератор — Qwen3.8-27B; модель судьи НЕ РАСКРЫВАЕТСЯ (Q&A33).
Public и private тесты различаются. Нет официальных ответов по каждому вопросу,
runtime-логов или точных эффективных параметров предыдущих загрузок.
Время не является членом формулы Score; timeout или пустые/технические ответы
могут косвенно испортить результат. «Успешно» означает принятый запуск, а не
доказательство правильности всех ответов.

ИТОГ ХАКАТОНА — ОТДЕЛЬНАЯ ФОРМУЛА
Онлайн: 50% LLM-судья + 50% экспертная оценка после приведения к одной шкале.
Экспертные веса онлайн: работоспособность 30%, качество консультации 25%,
скорость/стабильность 15%, архитектура 15%, безопасность/зависимости/документация
10%, презентация 5%. Каждая экспертная оценка выставляется по шкале 0–5.
Финал: онлайн 40% + защита 60%. Критерии защиты: ценность 25%, качество бота 25%,
техническая обоснованность 20%, внедрение 15%, защита/ответы 10%, владение командой 5%.
Допуск к экспертам: LLM >0, рабочий веб-чат с основным сценарием до заявки,
полный комплект обязательных материалов. Одного ZIP недостаточно для максимума
всего хакатона, хотя веб не нужен внутри автоматического CSV-сабмита.

ФОРМАТ И ЛИМИТЫ
solution.py, requirements.txt и нужные модули в корне без внешней папки.
Входные questions.csv и knowledge-base.zip предоставляет платформа; не включать
их в конкурсный ZIP. В этой передаче они включены как исходные материалы.
На выходе submission.csv, UTF-8, ровно id,answer; по одному непустому ответу
на каждый входной ID, без повторов и сторонних полей. Текст консультации — в answer.
Ответ до 10 000 символов; ориентир 150 слов, подробности разрешены по необходимости.
Каждый ID независим; история может быть внутри question. Отвечать на последнюю
реплику с учётом истории, не переносить состояние между ID.
5 сабмитов на команду за день, сброс 00:00 МСК; ZIP до 128 МБ; 8 CPU, 16 ГБ RAM;
20 минут исполнения. Не запускать pip install из solution.py. Использовать
разрешённые зависимости с точными версиями из приложенного requirements.txt;
стандартная библиотека не требует добавления сторонних пакетов.

ВАЖНОЕ ОБНОВЛЕНИЕ: ИНДЕКСЫ
Q&A32 разрешает готовые индексы в КОРНЕ ZIP рядом с solution.py. Старый запрет
регламента устарел именно в этой части. Это не разрешение класть любые данные,
веса или подпапки. Проверяй формат и совместимость embedding-векторов.

API
Адрес LLM_BASE_URL/OPENAI_BASE_URL, ключ LLM_API_KEY/OPENAI_API_KEY,
модель LLM_MODEL/OPENAI_MODEL/GEN_MODEL подставляет платформа.
Генерация: {base}/chat/completions, Authorization: Bearer {key}.
Для embeddings BAAI/bge-m3 и необязательного Qwen3 Reranker 8B используется тот же
прокси. Вход DATA_DIR, настройки TEMPERATURE, MAX_TOKENS, MAX_WORKERS, TOP_K,
CHUNKER, EMB_MODEL, RERANKER_MODEL, RERANKER_TOP_N доступны через окружение.
Используй модель из переменной; не зашивай локальный идентификатор в submission.
Thinking-токены входят в общий max_tokens (Q&A34). Следи за finish_reason,
reasoning_content и тем, что финальный content действительно сформирован.
Отдельного тестового прокси организаторы не предоставляют (Q&A38).
Точность, квантование и конфигурацию сервиса не раскрывают (11 ноября, 19:24).
Даже локальная Qwen3.8-27B не гарантирует идентичности платформенному инференсу.

КАЧЕСТВО КОНСУЛЬТАЦИИ И ЗАЯВКИ
Самые критичные ошибки: выдуманные факты, ответ не по существу, неподходящее
решение (Q&A4). Подбирать по потребности, не по одному слову или симптому.
Использовать базу, обязательные числовые рамки и запреты; не обещать экономию,
сроки, применимость или совместимость без основания. Предлагать подходящую
альтернативу, если основное решение не подходит. Мягко отвечать вне целевого
сегмента; бот ориентирован на посетителя сайта, а не только заданную роль.
Если данных недостаточно — полезное уточнение; если знаний нет — честно сказать
и предложить специалиста. Не выдавать сбой API за отсутствие знаний в базе.
При прямой просьбе связать со специалистом не продолжать длинную анкету (Q&A14).
Достаточно хотя бы одного контакта, прежде всего телефона; организация и регион
не обязательны (Q&A15). Сохранять уже оставленные сведения, не выдумывать их.
Резюме — основная потребность и существенный контекст, обычно 1–2 предложения
(Q&A16,20); посторонние общие вопросы не превращать в потребность клиента.
Не заявлять «отправлено», «менеджер позвонит» без реально выполненного действия.
Заявка оценивается в диалоге целиком (Q&A44–45). Демоответы — примеры, не шаблоны
для дословного копирования. Новые продуктовые факты из веба не смешивать с базой.

ВЕБ И ОРГАНИЗАЦИЯ
Самостоятельного чата достаточно; интеграция с сайтом, отдельная авторизация,
роли сотрудников, кабинет менеджера и CRM не обязательны. Нужны консультация,
заявка в человекочитаемом виде, отладка с временем и использованными документами.
Целевой ответ около 5–7 секунд; более 10 заметно (Q&A27). Это UX-ориентир,
не дополнительный множитель автоматического Score.
Собственный доступ к модели для веб-демо; ключи для демо не выдаются.
На вопрос о разрешении отдельной локальной модели для демо в сохранённой переписке
нет окончательного ответа: встречный вопрос организатора не равен разрешению.
Приватный репозиторий GitHub/GitLab с доступом жюри достаточен (Q&A49).
Кейс требует тестовые контакты и отсутствие опубликованных API-ключей.
