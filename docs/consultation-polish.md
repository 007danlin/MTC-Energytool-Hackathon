# Обновление оформления консультации · 14 ноября 2026

Рабочая страница: `http://127.0.0.1:8768/consultation.html`.

Первое обновление затрагивало оформление; последующие исправления добавили накопление подтверждённых фактов, передачу состояния модели и номера заявок. Существующие сессии и внутренние идентификаторы сохранены:

- Три стартовые карточки с локальными SVG-иллюстрациями. Выбор подставляет вопрос без отправки; выбранная карточка отмечается явно.
- Две карточки следующего действия: заявка специалисту и продолжение разговора. При продолжении они скрываются до следующего ответа.
- В левой панели первоначально показаны два пункта каждого списка. «Показать ещё» раскрывает остаток, «Весь список» открывает полную карточку. Длинные одиночные строки также можно раскрыть. Новые значения выводятся первыми; уже прочитанные сохраняют порядок в рамках страницы.
- Форма начинается с телефона/email, затем идут необязательные имя и компания. Резюме беседы можно просмотреть до проверки заявки.
- Справа на экранах от 1280 px отображается план. На меньших экранах он открывается кнопкой в отдельной панели. При вводе текст автоматически переносится при изменении ширины окна.

План копирует до восьми явно сформулированных действий из последнего сохранённого ответа со статусом `answered` или `clarification`, в котором такие действия удалось распознать. Основной источник — `summary.action_plan`; каждый шаг проверяется на наличие в тексте ответа. Для старых сессий работает разбор глаголов, инфинитивов и нумерации в одной строке. Это не дополнительный вызов модели и не полный семантический разбор ответа. Доступен исходный ответ. Уточняющие вопросы и этапы ожидания сами по себе план не создают. При следующем ответе без новых действий сохраняется предыдущий план с его исходным ответом.

Галочки ставит только пользователь. Они сохраняются в `localStorage` отдельно для каждой сессии и точного текста шага. Эти отметки не отправляются в backend, не переносятся между браузерами и не означают подтверждение выполнения консультантом.

После сохранения заявки backend выдаёт `application.number` — шесть цифр от 100000 до 999999, уникальных в текущем хранилище. Этот номер показан крупно на экране результата, в кнопке над чатом, истории и TXT-экспорте. Он сохраняется при редактировании контактов и перезапуске. Внутренний `application.id` остаётся прежним. Старым сохранённым заявкам номер присваивается при загрузке хранилища; исходные UUID и содержание не меняются.

Проверки: `tools/host_tests/test_consultation_polish.cjs` использует изолированный API с тестовыми ответами и проверяет сценарии, раскрытие фактов, план, сохранность отметок, разделение сессий, экранирование, форму, черновик, reduced motion и семь ширин 320–1920 px. Проверки интерфейса не оценивают качество рекомендаций модели.

Пересборка только веб-интерфейса: `docker compose -f compose.web.yaml up -d --build --no-deps web`. Данные диалогов и контейнеры backend/consultation сохраняются.
