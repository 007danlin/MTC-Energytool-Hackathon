# МТС Energytool: ИИ-консультант для сайта

Hack&Change 2026, кейс МТС. Клиент описывает задачу своими словами. Бот уточняет ситуацию, подбирает решение **только из базы знаний**, честно говорит «в базе этого нет» и собирает заявку для менеджера.

Состояние на 14 ноября 2026. Если что-то из описанного не работает, сначала смотрите раздел «Известные ограничения».

## Как проверить основной сценарий

Нужно:
- Docker Desktop;
- файл базы знаний `data/knowledge-base.zip` (его выдали организаторы; в репозитории базы нет, это условие кейса);
- доступная языковая модель: любой OpenAI-совместимый адрес с ключом.

```bash
cp .env.web.example .env.web      # впишите свои LLM_BASE_URL, LLM_API_KEY, LLM_MODEL
mkdir -p data && cp /путь/к/knowledge-base.zip data/
docker compose -f compose.web.yaml up --build -d
```

Откройте **http://127.0.0.1:8768** и нажмите «Онлайн-консультация».
Остановить: `docker compose -f compose.web.yaml down` (`down -v` ещё и удалит историю диалогов).

Что проверить:

1. Задайте вопрос своими словами. Бот отвечает по базе знаний, обычно с уточняющим вопросом.
2. Спросите то, чего в базе нет. Бот скажет об этом прямо и предложит связаться со специалистом.
3. Меню → «Включить режим отладки»: у каждого ответа видно время и использованные документы базы знаний.
4. Меню → «Подготовить заявку»: телефон обязателен, имя и компания нет. Сохраните заявку и скачайте TXT.
5. Меню → «Новый диалог»: контекст пустой. «История диалогов» хранит прежние сессии, в том числе без заявки.

Если модель недоступна, чат показывает техническую ошибку, но сессии, история и заявки продолжают работать.

## Как устроено

```text
Браузер ──> сайт (порт 8768) ──/api/v1──> Go API (8080) ──> консультант на Python (8090) ──> языковая модель
            чат, заявка,                  сессии, история,   поиск по базе знаний,             любой OpenAI-
            режим отладки                 заявки, хранение   промпт, проверка источников     совместимый адрес
```

- **Сайт** (`local-preview/energytool-site/`): копия сайта Energytool с кнопкой «Онлайн-консультация». Чат на весь экран по макету Figma, режим отладки, форма заявки.
- **Go API** (`backend/`): хранит сессии и всю историю, не смешивает диалоги, сохраняет ответ, источники и время, заявки. Данные лежат в JSON-файле (демо).
- **Консультант** (`consultation_http.py` и корневые `*.py`): ищет по базе знаний, строит ответ, проверяет, что источник реально был в найденном контексте.
- **Бизнес-логика** (`backend/internal/business/`, `backend/internal/expert/`): карточка потребности для менеджера, состояния заявки, метрики пилота, обращение к специалисту и проверенные знания. Контракты: `docs/business-contract.md`, `docs/expert-contract.md`.

Почему так, а не иначе: `docs/architecture-decisions.md`.

## Переменные окружения

| Переменная | Что это | По умолчанию |
|---|---|---|
| `LLM_BASE_URL` | адрес модели (OpenAI-совместимый) | в `.env.web.example` локальная Ollama |
| `LLM_API_KEY` | ключ доступа | заглушка `local-ollama` |
| `LLM_MODEL` | идентификатор модели | значение из `.env.web.example` |
| `MAX_WORKERS` | параллельных запросов к модели | 1 |
| `LLM_TIMEOUT` | таймаут одного запроса, секунд | 180 |
| `LLM_ATTEMPTS` | число попыток при сбое | 1 |
| `MAX_TOKENS` | предел длины ответа модели | 2048 |
| `CONTEXT_CHARS` | предел текста базы в запросе | 32000 |
| `WEB_PORT` | порт сайта на вашем компьютере | 8768 |
| `WEB_ENV_FILE` | другой файл с настройками | `.env.web` |

Ключи в репозиторий не кладём: `.env*` в `.gitignore`, в Git только `.env.example` и `.env.web.example` без секретов.

## Порты

- **8768** на `127.0.0.1`: сайт и чат. Единственный порт, открытый наружу контейнеров.
- 8080 (Go API) и 8090 (консультант) доступны только внутри сети Docker Compose.

## Зависимости

- Python: только стандартная библиотека. Файл `requirements.txt` пуст намеренно: сторонних пакетов нет, фиксировать нечего. В образе Python 3.11.
- Go: только стандартная библиотека, версия 1.22 и выше.
- Node.js и Playwright нужны только для браузерных тестов интерфейса.

## Тесты

```bash
python3 -m unittest discover -s tests -q       # консультант и HTTP-адаптер (на Windows: PYTHONUTF8=1)
cd backend && go vet ./... && go test -race ./...
```

Тесты проверяют логику и интеграцию на подставных данных, а не качество ответов модели.

## Известные ограничения

- **Модель и скорость.** Единственный живой замер веба: около 59 секунд на ответ с локальной моделью. Ориентир организаторов — 5–7 секунд. Платформенная модель из чата недоступна.
- **Веб отстаёт от конкурсной версии.** Веб использует более простой поиск (BM25 по разделам, версия A2), победивший N2 в чат пока не подключён.
- **Нет авторизации.** Демо работает на `127.0.0.1`. Выставлять в интернет нельзя без входа и ограничения запросов.
- **Хранилище — JSON-файл**, один процесс. Для рабочей системы нужна база данных.
- **Заявка не уходит в CRM.** Она сохраняется и скачивается внутри прототипа. Это условие кейса.
- **Карточка потребности и очередь заявок:** логика и тесты готовы (`backend/internal/business/`), экран очереди есть, подключение к API в работе.
- **Обращение к специалисту и пополнение базы:** логика готова, интеграция в API на проверке (PR #10), экран специалиста в работе.
- **Проверка источников** подтверждает, что фрагмент был в контексте, но не доказывает каждое утверждение ответа.
