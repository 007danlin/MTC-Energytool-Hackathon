# Финальные проверочные вопросы — шаблон для автора

Кто пишет: Артём (не видит ответов кандидатов A/B/C и их источников до фиксации финального варианта).
Когда: после того как параметры поиска заморожены (см. `docs/a3-retrieval-handoff.md`).
Куда: `data/eval/final_questions.json` (вне git до окончания сравнения), затем — в `eval/`.

## Сколько и каких

24 вопроса, по 3–4 на каждый тип ниже. Формулировки свои, не перефразы вопросов из `eval/cases_v3.json`.

| Тип | Что проверяет | Пример (не использовать как есть) |
|---|---|---|
| Многоходовое исправление | клиент поправил число/объект — бот учитывает новое | «у нас 900 кВт… нет, 600» |
| Отрицание | «нам НЕ нужен резерв, только экономия» | — |
| Короткая реплика в диалоге | «а цена?», «а если ночью?», «а вода?» | — |
| Ограничение сегмента | клиент вне целевой группы | сбытовая компания и поиск потерь |
| Подбор альтернативы | продукт не подходит — есть ли релевантная замена в базе | офисный центр и опт |
| Числа около порогов | 660/670/700, 740/750, 14/15/16 кВт, 19/20 МВт | — |
| Нет ответа в базе | реальный вопрос клиента, которого база не покрывает | — |

## Формат одной записи

```json
{
  "id": "f001",
  "type": "correction",
  "question": "Пользователь: ...\nАссистент: ...\nПользователь: ...",
  "expected": "1–2 предложения: что бот обязан сказать",
  "required_facts": [{"fact": "...", "where": "файл базы и раздел, где это написано"}],
  "conditional_facts": [{"condition": "...", "fact": "..."}],
  "forbidden_claims": ["что бот говорить не должен"],
  "acceptable_unknowns": ["чего в базе нет и это нормально"]
}
```

`source_id` и цитаты проставит скрипт сверки (`tools/build_eval_v3.py`); автору достаточно указать файл и раздел.

## Правила

- Каждый факт проверить по базе знаний (`data/knowledge-base.zip`) до записи.
- Не смотреть ответы и найденные источники вариантов A/B/C, пока набор не заморожен.
- После заморозки набор не меняем; если по нему что-то поправили в поиске — для новой проверки нужен новый набор.
